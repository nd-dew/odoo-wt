# Odoo Worktree Tool - v1.1.0 Roadmap

This document outlines the planned features, fixes, and improvements for the next major release (`v1.1.0`) of the `odoo-wt` tool.

## 🚀 1. Fully Integrated Deployment Screen
Currently, the tool drops out of the Textual TUI and back to the standard terminal to run `git` and `uv` commands using Rich. While reliable, this breaks the application's immersion.

**Goal:** Keep the user inside the TUI for the entire lifecycle.
- [ ] Create a new `DeploymentScreen` (Modal or full Screen) that appears when "Create" is clicked.
- [ ] Display individual, reactive Progress Bars for:
  - `git fetch` / `worktree add` (Community)
  - `git fetch` / `worktree add` (Enterprise)
  - `uv venv` / `pip install`
- [ ] Implement a scrolling `RichLog` widget at the bottom of the screen to stream the live stdout/stderr from the Git and UV subprocesses.
- [ ] Use Textual `@work(thread=True)` workers to ensure the UI remains snappy and responsive while the heavy shell commands run in the background.

## 🐛 2. Bug Fixes & Type Safety
- [ ] **Selector Value Fix:** Currently, if a user submits the form with certain dropdown states, the values evaluate to `Select.BLANK` instead of an empty string, causing `"Select.BLANK"` to literally appear in branch names or paths. Ensure all Select widget outputs are properly coerced to empty strings (`""`) before being used in path construction or summaries.

## ⌨️ 3. Quality of Life (QoL) & Shortcuts
- [ ] **Enter Key Submission:** Allow users to press `<Enter>` while focused on text inputs (like the Custom Suffix or Description fields) to instantly trigger the "Create" action, rather than requiring them to press `<Ctrl+S>` or tab to the button.
- [ ] **Focus Management:** Ensure that after a successful deployment or a cancelled action, the focus returns to a logical, safe place in the UI.
